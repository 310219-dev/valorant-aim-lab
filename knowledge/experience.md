# 開發經驗

## 暫停與續練要保留同一輪狀態

- **觀察：** 暫停流程保留了畫面上的命中與反應數據，並顯示「繼續訓練」，但開始函式會無條件清空統計；使用者續練後，畫面承諾與實際行為不一致。
- **做法：** 以既有 `paused` 狀態區分新的一輪與續練。續練時保留統計、目標節點與剩餘時間，暫停目標動畫；移動更新重啟時保留當前場景位移，只有新開一輪才重設統計與場景。
- **適用範圍：** 任何有「暫停／繼續」控制且需保存本輪進度的單頁互動工具；修改開始流程時，檢查暫停後是否走到新工作階段的初始化分支。
- **限制與後續：** 分頁進入背景仍受瀏覽器計時節流；若需跨分頁或關閉後恢復，應保存完整快照並以時間戳重算倒數。


## 移動停止判定應與實際速度一致

- **觀察：** 場景採慣性滑動，但「停止」狀態曾在速度仍高於 0 時提早顯示；射擊判定只讀這個狀態，因此玩家可能在場景仍移動時開火。
- **做法：** 無方向輸入時持續衰減速度，低於極小閾值後將速度明確歸零；移動狀態和射擊限制都以方向輸入或非零速度為準。
- **適用範圍：** 使用慣性／加速度的遊戲控制、拖曳或動畫互動；所有「已停止」或「可操作」狀態都應由實際物理狀態推導，不能只依賴較寬鬆的顯示閾值。
- **限制與後續：** 位移速度、邊界與停止閾值已按舞台大小比例換算，並以 650×500px 作為手感基準；若調整舞台設計尺寸，應重新檢查基準值。


## 互動訓練提示要連到可操作的目標

- **觀察：** 預瞄模式提示「揭露目標」，但流程只在兩段文字間循環，沒有實際目標；文字提示與訓練行為脫節。
- **做法：** 將每個角度拆成提示階段與揭露階段；按鈕明確揭露近角／遠角目標，命中或錯過後才排入下一個角度。
- **適用範圍：** 教學、導覽、逐步檢查和模擬訓練；凡是提示文案描述某個後續動作，都要確認介面確實提供該動作及可觀察結果。
- **演進：** 後續已加入左近、右遠、左深、右近四個角度並改為場景資料驅動；預瞄靶停留時間目前可獨立調整並儲存在本機。


## 逐步訓練內容適合用場景資料驅動

- **觀察：** 預瞄流程原本用奇偶判斷切換兩個固定角度，文案、提示和目標座標分散在條件式中；每增加一個角度都容易漏改其中一段。
- **做法：** 把角度名稱、教練提示、確認問題與目標座標集中成資料項目，流程只負責輪替目前項目並呈現其內容。
- **適用範圍：** 逐步導覽、教學卡、測驗關卡與任何由內容驅動的分段互動；當分支主要差異是文字和參數時，優先用資料描述差異。
- **限制與後續：** 現階段位置仍是相對舞台的百分比座標，所有角度共用單一背景場景；若加入多張地圖或障礙物遮蔽，應把背景與座標一起定義成場景設定。


## 暫停互動時要封存倒數與動態效果

- **觀察：** 只保留分數不足以代表真正續練；暫停期間目標若被刪除或倒數繼續，玩家回來時會失去當前情境。
- **做法：** 暫停時計算目標剩餘時間、隱藏目標並暫停其 Web Animations；續練時還原同一個節點與動畫，再以剩餘時間重新啟動逾時器。切換模式或重設時明確丟棄封存目標。
- **適用範圍：** 有逾時事件或播放中動畫的互動練習、遊戲與媒體介面；暫停／恢復應同時處理計時器、動畫、畫面節點和輸入狀態。
- **限制與後續：** 瀏覽器分頁進入背景時仍由瀏覽器節流計時；若需要跨分頁或關閉後恢復，應改用時間戳與持久化快照。


## Pages 部署前確認 artifact 已可讀

- **觀察：** `deploy-pages` 透過 Actions Results artifact service 列舉檔案；GitHub REST artifacts API 已回報可見時，Pages service 仍可能回報 0 個 artifact。
- **處理：** 在部署步驟前使用 `actions: read` 輪詢當前 run 的 artifact 清單，確認可讀後再等 8 秒，給 Pages service 同步時間；等待 30 秒仍不可讀時明確失敗。
- **適用範圍：** 上傳 artifact 與消費 artifact 分屬不同 Actions 步驟／服務、且讀取端可能早於索引更新的流程。
- **驗證與限制：** 加入 8 秒同步等待後，run `45934112673` 的 Deploy site 成功；總等待最多約 38 秒，仍需觀察後續 run 確認穩定性。


## 暫停時保留場景座標系

- **觀察：** 即使保留目標 DOM 和倒數，若暫停時把相機／世界位移重置，目標相對背景仍會跳位，續練不算恢復同一情境。
- **做法：** 停止動畫迴圈並清空輸入與速度，但保留玩家位移及世界 transform；只有新回合或結束回合才重置場景。
- **適用範圍：** 將相機、角色或世界座標變換用於場景移動的互動介面；暫停狀態需一起保存座標系和畫面內容。
- **限制與後續：** 目前只保存頁面記憶體中的水平／垂直位移，不支援重新整理後恢復。


## 暫停與續練要遵守模式專屬輸入

- **觀察：** 預瞄模式不使用 WASD，但共用續練分支曾啟動移動迴圈並隱藏指標，造成同一模式在開始與續練後的操作狀態不同。
- **做法：** 續練時依目前模式恢復相應的輸入與游標行為；開始預瞄新回合時清理舊的移動狀態與場景位移。
- **適用範圍：** 多模式互動工具共用一個開始／暫停控制時；在恢復工作階段前，按模式重新套用輸入、游標和動畫政策。
- **限制與後續：** 目前模式差異仍以條件分支管理；若增加更多模式，可將開始、暫停與恢復行為抽成模式設定。


## 切換模式時同步重設數據和提示

- **觀察：** 模式切換只更新選中按鈕與標題，輪次和統計仍顯示上一模式的資料；重設按鈕也可能把預瞄模式帶回一般射擊提示。
- **做法：** 模式切換時清空本輪統計並更新輪次；把共用的開始提示集中在一個函式，依目前模式填入標題、說明和按鈕文字。
- **適用範圍：** 在多模式介面重用統計面板或開始彈層；切換情境時同步重設所有只屬於舊情境的狀態與文案。
- **限制與後續：** 目前切換模式會捨棄舊回合統計；若未來需要跨模式比較，應先保存每輪摘要再清除畫面。


## 使用者可調設定適合保存在本機

- **觀察：** 靈敏度、目標數和練習偏好若只存在記憶體，重整或再次打開頁面便回到預設，增加重複設定成本。
- **做法：** 只儲存經驗證的選項值到 `localStorage`，讀取時驗證允許值並以 try/catch 處理儲存空間受限的情況；回合統計不寫入偏好設定。
- **適用範圍：** 無帳號的單頁工具、原型和本機偏好；儲存非敏感 UI 選項，明確告知使用者資料存放在目前瀏覽器。
- **限制與後續：** 瀏覽器清除網站資料或使用其他裝置時設定不會同步；若未來需要跨裝置保存，需另行設計後端和明確的同步方式。


## 設定變更時保留目前模式與階段文案

- **觀察：** 目標數選項共用一般射擊說明；在預瞄提示階段改數量會用不相干的「點擊射擊」文字覆蓋當前角度提示。
- **做法：** 設定變更只更新受影響的統計／回合數；若目前顯示的是模式專屬提示，重繪同一階段的文案；暫停時保留暫停提示。
- **適用範圍：** 設定可在多模式介面即時修改，且不同模式有不同引導文案的產品。
- **限制與後續：** 目前改變目標數會影響正在進行的回合總數；未來若想鎖定回合設定，需明確定義何時套用新值。


## 不同訓練模式要有不同的核心任務

- **觀察：** 轉點反應模式原本只改變標籤，靶位仍與定點模式採相同隨機範圍，實際練習沒有轉點所需的大幅移動。
- **做法：** 依上一靶位置抽取新靶位，要求兩靶距離至少為舞台寬度的 28%（窄螢幕至少 120px），並提供清楚的模式專屬目標與教練提示。
- **適用範圍：** 多模式訓練工具；檢查模式標籤背後的任務規則是否真的不同，並以最小位移等可量化條件表達練習目標。
- **限制與後續：** 目前使用像素距離門檻與隨機取樣；若要調整難度，可依玩家試玩結果調整最小轉點距離或目標區域。


## 分頁進入背景時自動暫停訓練

- **觀察：** 背景分頁的計時器會被瀏覽器節流；即使暫停流程能保存目標剩餘時間，玩家切回時也可能因計時器延遲而失去當前目標。
- **做法：** 在 `visibilitychange` 發現文件隱藏時呼叫既有暫停流程，沿用其對目標剩餘時間、動畫、場景位移與回合數據的保存；回到頁面後由玩家按繼續，避免意外自動射擊或恢復輸入。
- **適用範圍：** 使用倒數、動畫或即時輸入的瀏覽器訓練與遊戲；當瀏覽器背景節流會改變互動結果時，將分頁可見狀態納入生命週期管理。
- **限制與後續：** 僅偵測頁面可見性變化；若瀏覽器或作業系統暫停整個程序而頁面狀態未更新，仍需以時間戳或頁面恢復事件補強。


## 自訂按鈕狀態要提供語意資訊

- **觀察：** 模式選擇和偏好開關只透過 CSS 樣式呈現狀態，輔助技術無法讀出目前選取或開啟與否。
- **做法：** 對可切換按鈕使用 `aria-pressed` 表示目前狀態；互動時同步更新所有互斥模式的選取值，載入本機偏好後再同步開關狀態。
- **適用範圍：** 使用自製按鈕呈現切換器、篩選器或互斥選項的網頁；任何視覺狀態都應有等效的可讀語意。
- **限制與後續：** `aria-pressed` 只能說明按鈕是否按下；若未來改用原生 checkbox 或 switch role，應按新控件語意改用相應狀態屬性。


## 響應式舞台縮放要保留準心相對位置

- **觀察：** 舞台尺寸會隨視窗改變，但準心位置以像素保存；縮放後舊座標可能偏離原本的相對位置，甚至被裁出舞台。
- **做法：** 以 `ResizeObserver` 監聽舞台寬高變化，依新舊尺寸比例換算準心位置，再重繪並套用既有邊界限制。
- **適用範圍：** 使用相對尺寸自適應、但內部互動座標仍以像素保存的畫布或遊戲舞台。
- **限制與後續：** 準心保持相對位置，不會刻意跟隨實體滑鼠在 resize 前的位置；若玩家回報縮放後指標感受不一致，再明確定義準心與指標的同步政策。


## 移動速度和邊界要按舞台大小縮放

- **觀察：** WASD 的速度和最大位移使用固定像素；同一組數值在窄舞台上占更大比例，造成移動與急停手感改變。
- **做法：** 以 650×500px 為參考舞台，速度、位移邊界和停止閾值都按目前舞台寬高比例換算；舞台變更尺寸時也同步縮放當前場景位移與殘餘速度。
- **適用範圍：** 依 viewport 或容器縮放的互動畫布、遊戲場景和模擬器；將像素物理量轉成相對於工作區的尺度，確保不同尺寸有近似手感。
- **限制與後續：** 參考尺寸與速度仍是目前原型的手感基準；若玩家回報特定尺寸下過快或過慢，再據回饋調整基準值。


## 預瞄訓練要避免可預測的角度順序

- **觀察：** 四個角度雖然輪替完整，但固定順序會讓玩家記住下一靶位置，減少讀角與臨場轉移的練習。
- **做法：** 每批先將四個角度洗牌，確保一批各出現一次；洗牌邊界若與上一個角度重複，就交換前兩項。
- **適用範圍：** 順序記憶會干擾目標能力的訓練、測驗題或逐步練習；以隨機排列加上平衡袋維持覆蓋率且降低猜測。
- **限制與後續：** 每批四個角度覆蓋均衡，但短期內仍可能在連續批次裡重複多個角度；若需要精確難度進程，可改成按反應或命中情況排序。


## 模式專屬的難度設定應獨立保存

- **觀察：** 預瞄目標原本固定存活 5 秒，無法配合不同玩家的讀角與射擊速度；一般靜止靶設定也不應暗中改變預瞄節奏。
- **做法：** 加入獨立的預瞄靶停留設定，提供 2、3、5、8 秒選項，預設維持原本 5 秒；將值加入經驗證的本機偏好資料。
- **適用範圍：** 同一產品內各模式有不同任務節奏時；使用明確模式專屬控制，避免一項全域設定產生不直覺的跨模式副作用。
- **限制與後續：** 對已揭露的目標變更設定，只影響下一個預瞄目標，不會重設當前倒數；難度評估仍應結合玩家實際試玩回饋。


## 動態目標要把自身尺寸納入舞台邊界

- **觀察：** 移動靶原本使用固定水平動畫距離；靶位靠近舞台邊緣或畫面較窄時，目標可能被推到可視範圍外。
- **做法：** 讀取目標本體、標籤和舞台的實際邊界，將動畫幅度限制在三者到最近邊緣的可用空間內。
- **適用範圍：** 有固定或隨機尺寸的動畫物件；設定移動距離時，應一併考慮物件外框、標籤和容器邊界。
- **限制與後續：** 若物件同時受到多個父層變換或動態容器裁切，需在每個動畫影格重新量測可用空間；目前只保證動畫自身水平移動不會超出當下測得的舞台邊界。
