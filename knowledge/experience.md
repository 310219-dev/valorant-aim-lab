# 開發經驗

## 暫停與續練要保留同一輪狀態

- **觀察：** 暫停流程保留了畫面上的命中與反應數據，並顯示「繼續訓練」，但開始函式會無條件清空統計；使用者續練後，畫面承諾與實際行為不一致。
- **做法：** 以既有 `paused` 狀態區分新的一輪與續練。續練時保留統計、目標節點與剩餘時間，暫停目標動畫；移動更新重啟時保留當前場景位移，只有新開一輪才重設統計與場景。
- **適用範圍：** 任何有「暫停／繼續」控制且需保存本輪進度的單頁互動工具；修改開始流程時，檢查暫停後是否走到新工作階段的初始化分支。
- **限制與後續：** 分頁進入背景仍受瀏覽器計時節流；若需跨分頁或關閉後恢復，應保存完整快照並以時間戳重算倒數。


## 移動停止判定應與實際速度一致

- **觀察：** 場景採慣性滑動，但「停止」狀態曾在速度仍高於 0 時提早顯示；射擊判定只讀這個狀態，因此玩家可能在場景仍移動時開火。
- **做法：** 無方向輸入時持續衰減速度，低於極小閾值後將速度明確歸零；移動狀態和射擊限制都以方向輸入或非零速度為準。
- **適用範圍：** 使用慣性／加速度的遊戲控制、拖曳或動畫互動；所有「已停止」或「可操作」狀態都應由實際物理狀態推導，不能只依賴較寬鬆的顯示閾值。
- **限制與後續：** 目前速度閾值以像素／秒表示，未按畫面縮放正規化；若要跨尺寸比較動作手感，可改用相對場景尺寸或時間常數。


## 互動訓練提示要連到可操作的目標

- **觀察：** 預瞄模式提示「揭露目標」，但流程只在兩段文字間循環，沒有實際目標；文字提示與訓練行為脫節。
- **做法：** 將每個角度拆成提示階段與揭露階段；按鈕明確揭露近角／遠角目標，命中或錯過後才排入下一個角度。
- **適用範圍：** 教學、導覽、逐步檢查和模擬訓練；凡是提示文案描述某個後續動作，都要確認介面確實提供該動作及可觀察結果。
- **演進：** 後續已加入左近、右遠、左深、右近四個角度並改為場景資料驅動；目前仍共用同一背景，目標存活時間固定 5 秒。


## 逐步訓練內容適合用場景資料驅動

- **觀察：** 預瞄流程原本用奇偶判斷切換兩個固定角度，文案、提示和目標座標分散在條件式中；每增加一個角度都容易漏改其中一段。
- **做法：** 把角度名稱、教練提示、確認問題與目標座標集中成資料項目，流程只負責輪替目前項目並呈現其內容。
- **適用範圍：** 逐步導覽、教學卡、測驗關卡與任何由內容驅動的分段互動；當分支主要差異是文字和參數時，優先用資料描述差異。
- **限制與後續：** 現階段位置仍是相對舞台的百分比座標，所有角度共用單一背景場景；若加入多張地圖或障礙物遮蔽，應把背景與座標一起定義成場景設定。


## 暫停互動時要封存倒數與動態效果

- **觀察：** 只保留分數不足以代表真正續練；暫停期間目標若被刪除或倒數繼續，玩家回來時會失去當前情境。
- **做法：** 暫停時計算目標剩餘時間、隱藏目標並暫停其 Web Animations；續練時還原同一個節點與動畫，再以剩餘時間重新啟動逾時器。切換模式或重設時明確丟棄封存目標。
- **適用範圍：** 有逾時事件或播放中動畫的互動練習、遊戲與媒體介面；暫停／恢復應同時處理計時器、動畫、畫面節點和輸入狀態。
- **限制與後續：** 瀏覽器分頁進入背景時仍由瀏覽器節流計時；若需要跨分頁或關閉後恢復，應改用時間戳與持久化快照。


## Pages 部署前確認 artifact 已可讀

- **觀察：** 兩次 GitHub Pages workflow 都在 artifact 上傳成功後約 0.3 秒內，由 `deploy-pages` 查到 0 個 `github-pages` artifact；事後查同一 run 的 artifacts API 已能看到檔案，符合可見性延遲。
- **處理：** 在部署步驟前使用具有 `actions: read` 的 token 輪詢當前 run 的 artifact 清單，檔案可讀後才執行部署；等待 30 秒仍不可讀時明確失敗。
- **適用範圍：** 上傳 artifact 與消費 artifact 分屬不同 Actions 步驟／服務、且讀取端可能早於索引更新的流程。
- **限制與後續：** 輪詢增加最多 30 秒部署等待；最新 workflow 成功後再確認此處理是否穩定有效。


## 暫停時保留場景座標系

- **觀察：** 即使保留目標 DOM 和倒數，若暫停時把相機／世界位移重置，目標相對背景仍會跳位，續練不算恢復同一情境。
- **做法：** 停止動畫迴圈並清空輸入與速度，但保留玩家位移及世界 transform；只有新回合或結束回合才重置場景。
- **適用範圍：** 將相機、角色或世界座標變換用於場景移動的互動介面；暫停狀態需一起保存座標系和畫面內容。
- **限制與後續：** 目前只保存頁面記憶體中的水平／垂直位移，不支援重新整理後恢復。


## 暫停與續練要遵守模式專屬輸入

- **觀察：** 預瞄模式不使用 WASD，但共用續練分支曾啟動移動迴圈並隱藏指標，造成同一模式在開始與續練後的操作狀態不同。
- **做法：** 續練時依目前模式恢復相應的輸入與游標行為；開始預瞄新回合時清理舊的移動狀態與場景位移。
- **適用範圍：** 多模式互動工具共用一個開始／暫停控制時；在恢復工作階段前，按模式重新套用輸入、游標和動畫政策。
- **限制與後續：** 目前模式差異仍以條件分支管理；若增加更多模式，可將開始、暫停與恢復行為抽成模式設定。


## 切換模式時同步重設數據和提示

- **觀察：** 模式切換只更新選中按鈕與標題，輪次和統計仍顯示上一模式的資料；重設按鈕也可能把預瞄模式帶回一般射擊提示。
- **做法：** 模式切換時清空本輪統計並更新輪次；把共用的開始提示集中在一個函式，依目前模式填入標題、說明和按鈕文字。
- **適用範圍：** 在多模式介面重用統計面板或開始彈層；切換情境時同步重設所有只屬於舊情境的狀態與文案。
- **限制與後續：** 目前切換模式會捨棄舊回合統計；若未來需要跨模式比較，應先保存每輪摘要再清除畫面。
